Déployer RAGDom sur le web, gratuitement

La version web complète (UI + API + moteur d'ingestion sci-engine) tient dans une seule image Docker servie par un seul processus. Ce guide couvre les hébergeurs gratuits qui savent l'exécuter — et explique pourquoi certains (Vercel, Cloudflare) ne servent que l'interface.

⚠️ La seule vraie limite du 100 % gratuit : les offres gratuites (HF Spaces, Render, Koyeb) ont un stockage éphémère — au redémarrage du conteneur, les bases .sqlite uploadées sont perdues. Deux parades : ① ingérer localement puis ré-uploader la base finie (fichier unique, grâce à la Base Autonome V3.5) après chaque redémarrage — parfait pour démo/consultation ; ② passer à un plan avec volume (Railway/Fly/HF persistent ~5 $/mois) pour la persistance réelle.

01Hugging Face Spaces — ⚠️ devenu PAYANT pour Docker (vérifié en conditions réelles)

Testé le 21/08/2026 avec un vrai compte : l'API HF répond désormais 402 — « hosting Gradio and Docker Spaces on free cpu-basic requires a PRO subscription ». Les Spaces Docker (privés ET publics) exigent l'abonnement HF PRO. Le gratuit de référence devient Render (§2) — la section ci-dessous reste valable pour les abonnés PRO.
1

Créer le Space

Sur huggingface.co (compte gratuit) → New Space → Name : ragdom → SDK : Docker → Blank → Visibility : Private (recommandé) → Create.

2

Pousser le code de la branche post-v1

git clone -b post-v1 https://github.com/amichiamine/RAGDom.git
cd RAGDom
git remote add space https://huggingface.co/spaces/<TON_USER>/ragdom
git push space post-v1:main

(À la demande de mot de passe : un token HF « write », créé dans Settings → Access Tokens.)

3

Déclarer le port : ajouter en TÊTE du fichier README.md du Space

---
title: RAGDom
sdk: docker
app_port: 8000
---

HF attend le port 7860 par défaut ; cette entête lui indique que RAGDom écoute sur 8000.

4

Variables d'environnement (Settings → Variables and secrets du Space)

RAGDOM_READONLYtrue pour une bibliothèque de consultation publique · false pour l'atelier complet (alors définis le jeton ↓) RAGDOM_AUTH_TOKEN(secret) un long jeton aléatoire — requis si READONLY=false : protège ingestion/purge/clés RAGDOM_ALLOW_REVEALfalse — TOUJOURS sur le web RAGDOM_ASK_RATE_PER_MIN6 — protège tes clés LLM
5

C'est en ligne

Le Space builde l'image (npm run build + backend, ~10 min la première fois) puis sert https://<user>-ragdom.hf.space — l'UI ET l'API sur la même URL. Premier démarrage : les modèles OCR/embeddings se téléchargent automatiquement (RAGDOM_OFFLINE=false par défaut dans l'image).

Charger une bibliothèque : ingère localement, puis Vue 3 → Bases → Exporter, et re-upload du .sqlite via l'atelier web (mode non-readonly) — ou commite le fichier dans le Space (dossier monté vers /data via une ligne COPY ajoutée au Dockerfile si tu veux des bases pré-chargées permanentes, immunisées contre les redémarrages).

02Render.com — gratuit, URL propre, veille automatique

1

render.com → New → Web Service → connecte GitHub → repo RAGDom → Branch : post-v1.

2

Language : Docker (le Dockerfile racine est détecté) · Instance type : Free · même variables d'environnement qu'au §1.4.

3

Deploy → https://ragdom.onrender.com.

Limites du plan Free : mise en veille après 15 min d'inactivité (premier accès suivant : ~1 min de réveil) · 512 Mo RAM — suffisant pour la consultation (readonly), trop juste pour l'ingestion OCR de gros scans → fais l'ingestion en local et publie les .sqlite.

03Railway — le plus confortable (essai gratuit puis ~5 $/mois)

1

railway.app → New Project → Deploy from GitHub repo → RAGDom → Branch post-v1. Le Dockerfile est utilisé automatiquement.

2

Ajoute un Volume monté sur /data (clic droit sur le service → Attach Volume) → tes bases, sources et modèles persistent entre les redéploiements. Variables du §1.4 + Settings → Networking → Generate Domain (port 8000).

3

C'est l'option « je veux le vrai atelier complet sur le web » : RAM configurable, ingestion à distance viable, persistance réelle.

04Cloudflare — vitrine UI (ton pipeline actuel)

Cloudflare Workers/Pages ne peut pas exécuter le backend Python (binaires natifs — voir le schéma §00). Il sert en revanche parfaitement l'UI seule :

1

Dans ton projet Cloudflare : Production branch : post-v1 (recommandé désormais — c'est la branche web de référence ; main fonctionne aussi pour l'UI). Root directory : frontend. Le wrangler.jsonc livré supprime l'erreur « Vite ≥ 6 » : relance le déploiement, il passe.

2

Variable de build VITE_API_URL=https://<ton-backend> (l'URL HF/Render/Railway du §1-3) — et côté backend, ajoute ton domaine Cloudflare dans FRONTEND_URL (liste CORS). Sans backend : l'UI s'affiche avec l'écran « aucun backend joignable » (normal).

Astuce : si tu déploies via §1-3, Cloudflare devient optionnel — l'image Docker sert déjà l'UI. Garde Cloudflare seulement si tu veux son CDN devant l'UI.

4bisCloudflare Containers — le déploiement COMPLET via Cloudflare (GA avril 2026)

Vérifié sur la documentation officielle : Cloudflare Containers est en disponibilité générale depuis le 13/04/2026 — on peut désormais exécuter l'image Docker RAGDom entière (UI + API + moteur) sur le réseau Cloudflare. Condition : plan Workers Paid (5 $/mois) — les Containers ne sont pas dans le plan Free — + facturation à l'usage CPU actif (scale-to-zero : un site peu visité coûte quelques centimes).

1

Sur ta machine (Docker requis) :

git clone -b post-v1 https://github.com/amichiamine/RAGDom.git
cd RAGDom/deploy/cloudflare
npm install
npx wrangler deploy

Le dossier deploy/cloudflare/ du dépôt contient tout : le Worker de routage, la config wrangler.jsonc (containers + Durable Object) et le README détaillé. Wrangler builde l'image, la pousse au registre Cloudflare et publie https://ragdom-web.<compte>.workers.dev.

2

Gabarit : standard (4 GiB / ½ vCPU / 4 GB disque) — confortable pour RAGDom (pic mesuré : 489 Mo). Démarrage à froid : 1-3 s, veille automatique après 2 h sans trafic.

⚠️ Disque éphémère (limite plateforme) : à chaque mise en veille, le disque du conteneur repart de l'image — les .sqlite uploadés à chaud sont perdus. Parade recommandée : embarquer les bases dans l'image (une ligne COPY databases_publiees/*.sqlite /data/databases/ dans le Dockerfile — détaillé dans deploy/cloudflare/README.md). La bibliothèque de consultation renaît alors identique à chaque réveil. Cloudflare annonce des « snapshots » pour la persistance native.
Verdict : tu avais raison — Cloudflare peut tout héberger désormais. Choisis-le si tu es déjà dans son écosystème et que le trafic est en rafales (facturation CPU actif imbattable). Reste sur HF Spaces si tu veux du 100 % gratuit, ou Railway si tu veux un disque réellement persistant.
